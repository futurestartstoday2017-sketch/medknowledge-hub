# MedKnowledge Hub

製薬企業1社の製品と、その競合製品・関連疾患・添付文書などの公開情報を整理し、検索・比較・学習するための個人学習用アプリです。

> ⚠️ **このアプリは個人の学習・情報整理用です。実際の診療判断には使用しないでください。**
> 登録されている初期データは、すべて学習用の架空のものです。

## 基本方針

- 一般に公開されている情報のみを扱います。
- 医学的情報には出典（原文URL・版・確認日）をつけて登録します。
- 公開情報と自分の学習メモは区別して管理します。
- 製品同士を比較するときに、優劣を自動で判定することはしません。
- ローカルPCだけで動かします（外部公開やクラウドサービスは使いません）。

## 使用技術

| 技術 | 用途 |
|---|---|
| Python | プログラミング言語 |
| Streamlit | Webアプリの画面を作るライブラリ |
| SQLite | ファイル1つで動くデータベース |
| pandas | 表形式のデータ（CSVなど）を扱うライブラリ |
| pytest | 自動テストを実行するツール |

## 起動方法（Windows / VS Code のターミナル）

```powershell
# 1. 仮想環境を作る（初回のみ）
python -m venv .venv

# 2. 仮想環境を有効にする（ターミナルを開くたびに実行）
.venv\Scripts\Activate.ps1

# 3. ライブラリをインストールする（初回と、requirements.txt が変わったとき）
pip install -r requirements.txt

# 4. アプリを起動する（ブラウザが自動で開きます）
streamlit run app.py

# 5. 自動テストを実行する
pytest
```

アプリを止めるときは、ターミナルで `Ctrl + C` を押します。

## データベースについて

初めて `streamlit run app.py` を実行すると、`data/medknowledge.db` が自動で作られ、`data/samples/` の架空データ（製品3件・疾患2件など）が登録されます。
架空データの状態に戻したいときは、アプリを止めてから `data/medknowledge.db` を削除し、もう一度起動してください（削除する前にバックアップを取っておくと安心です）。

### 架空データと実データの切り替え

架空データ（動作確認用）と実データは、別々のデータベースに保存します。サイドバーの「データ管理」→「データベースの切り替え」で切り替えます。

| 種類 | ファイル | 中身 |
|---|---|---|
| 🧪 架空データ | `data/medknowledge.db` | 最初から架空のサンプルデータが入る |
| 📘 実データ | `data/medknowledge_real.db` | 架空データは入らない。実在の製品・試験などを登録する |

- 今どちらを使っているかは、すべての画面のサイドバーに表示されます。
- 切り替えても、もう一方のデータベースは消えません。
- 実データの取り込み用CSV（AIが調査して作成したものを含む）は `data/imports/` に置きます（GitHub には上がりません）。

## CSVでデータを取り込む

サイドバーの「データ管理」→「CSVインポート」から取り込めます。テンプレートは `data/templates/` にあり、画面からもダウンロードできます。

| テンプレート | 内容 |
|---|---|
| `companies.csv` | 企業（企業名・対象企業か） |
| `products.csv` | 製品（販売名・一般名・区分・公式製品URL・最終確認日） |
| `diseases.csv` | 疾患（疾患名・英語名） |
| `documents.csv` | 文書と版（文書種別・タイトル・版・改訂年月・入手日・原文URL・関連する製品/疾患 など） |
| `indications.csv` | 適応症（販売名・疾患名と、効能・効果の文言・出典） |
| `approvals.csv` | 承認（承認の種類・承認年月日・承認番号・出典） |
| `reexaminations.csv` | 再審査（公開状況・再審査期間・開始日・終了日・出典） |
| `patents.csv` | 特許（特許番号・種類・公開状況・存続期間満了日・延長登録後の満了日・出典） |
| `licenses.csv` | ライセンス（相手先の企業・役割・契約の種類・契約期間・開示年度・出典） |
| `pms_studies.csv` | PMS（調査の種類・全例調査か・承認条件か・実施状況・実施期間・登録番号・出典） |
| `trials.csv` | 臨床試験（1行＝1つの登録番号。同じ試験の別の登録番号は「同じ試験の登録番号」の列でまとめる） |

- 取り込む順番は「企業・製品・疾患 → 文書と版 → 適応症 → 承認・再審査・特許・ライセンス・PMS」です（先に登録したものを、あとのCSVで参照するため）。
- Excel で編集して「CSV（コンマ区切り）」または「CSV UTF-8」で保存したファイルを読み込めます。
- 誤りが1か所でもあれば何も登録せず、何行目のどこが誤りかを日本語で表示します。
- 取り込んだ医学的情報・規制情報（効能・効果の文言、承認、特許など）は「⚠️ 未確認」で登録されます。
- 公開状況が「非公開」「未確認」のときは、日付を空欄にします（推測で埋めないため）。
- 原文を確認したら、「更新管理」画面で「原文確認済み」にしてください。
- 登録するときに「このCSVを作成したのは 人 / AI」を選びます。AI（Claude など）が調査して作成したCSVは、入力方法が「AI抽出」として記録されます。
- 登録の前に、自動でバックアップを取ります。

## バックアップと復元

```powershell
# バックアップを作る（data/backups/ に「medknowledge_日時.db」として保存）
python -m db.backup backup

# バックアップの一覧を表示する
python -m db.backup list

# バックアップから復元する（先にアプリを Ctrl + C で止めてください）
python -m db.backup restore data\backups\medknowledge_20251020_153000.db
```

「更新管理」画面でデータを変更するときは、その画面を開いてから最初の変更の前に、自動でバックアップを取ります。
復元するときは、壊れていないかを自動でチェックします。また、復元前のデータベースも念のためバックアップとして残します。
データベースとバックアップは、GitHubにはアップロードされません。

## フォルダ構成

| 場所 | 役割 |
|---|---|
| `app.py` | 起動ファイル（共通設定とサイドバーのメニュー定義） |
| `pages/` | 各画面（ホーム・製品情報・疾患情報・競合製品比較・更新管理・データ管理） |
| `db/schema.sql` | データベースの設計図（バージョン1のテーブルの定義） |
| `db/migrations/` | 設計図の追加分（バージョン2以降。古いDBは起動時に自動で更新） |
| `db/database.py` | データベースへの接続・テーブル作成 |
| `db/changes.py` | 事実のデータを、更新履歴を残しながら登録・変更する処理 |
| `db/quality.py` | 出典と版の不整合を見つける品質チェック |
| `db/backup.py` | バックアップと復元 |
| `db/errors.py` | データベースのエラーを日本語の説明に直す処理 |
| `db/settings.py` | アプリの設定（前回の確認者名など）の保存 |
| `db/queries.py` | 画面に表示するデータを取り出す処理 |
| `components/display.py` | 画面で共通して使う表示の部品（確認状態の印・出典の表示など） |
| `services/search.py` | 横断検索（製品・疾患・文書・医学的情報をまとめて探す） |
| `services/comparison.py` | 競合製品比較の表と、出典の一覧を作る処理 |
| `services/updates.py` | 確認・更新管理の処理（内容の修正、新しい版の登録、変更候補） |
| `services/diff.py` | 変更前と変更後の差分を作る処理 |
| `services/timeline.py` | 初回承認から再審査期間の終了・特許満了までのタイムライン（期間の目安） |
| `services/fact_fields.py` | 事実のテーブルごとの「修正できる項目」の定義と、入力値の確認 |
| `services/trials.py` | 臨床試験を1行（1つの登録番号）ずつ登録する処理 |
| `services/csv_importer.py` | CSVの検証と取り込み |
| `services/sample_loader.py` | 架空データのCSVをデータベースに登録する処理 |
| `services/` | CSVインポートなど、画面から使う処理 |
| `data/templates/` | CSVインポート用のテンプレート（見出し行のみ） |
| `data/samples/` | 動作確認用の架空データ（CSV。初回起動時に自動で登録） |
| `data/medknowledge.db` | データベース本体（自動作成・Gitには含めない） |
| `data/backups/` | データベースのバックアップ（Gitには含めない） |
| `docs/design.md` | 設計書（テーブル・画面・開発計画） |
| `tests/` | 自動テスト |
| `.streamlit/config.toml` | 画面のテーマ（色）の設定 |
| `requirements.txt` | 必要なライブラリの一覧 |
| `.gitignore` | Gitに含めないファイルの一覧 |
| `CLAUDE.md` | Claude Code向けの作業ルール |
